01

Browser Pipeline
(HTML → Screen)

Before JavaScript can touch anything, the browser has to turn plain text into something it can draw. HTML and CSS take two parallel routes, then merge.

The rendering pipeline
HTML Parsing Tokenization DOM Tree
CSS Parsing CSSOM Tree
↓ DOM + CSSOM combine
Render Tree Layout Paint Screen

Walk through it

InteractiveStep 1 / 6

Key terms

TermMeaning
ParsingThe browser reads HTML top to bottom and understands its structure.
TokenizationBreaks HTML into tokens: Start Tag, End Tag, Text, Attribute.
DOMDocument Object Model, a tree of HTML objects.
CSSOMCSS Object Model, a tree of CSS rules.
Render TreeCombined visual structure. It ignores display: none.
LayoutCalculates the size and position of every element.
PaintDraws the actual pixels on screen.
Analogy · building a house

HTML = the materials. DOM = the blueprint. CSSOM = the decoration instructions. Render Tree = the final plan. Layout = measuring. Paint = building.

Note

An element with display: none exists in the DOM but not in the render tree. An element with visibility: hidden is in the render tree and takes up space; it just isn't painted.

02

DOM Basics

Core idea

The DOM is a live object tree, not the HTML text itself. JavaScript manipulates the DOM, never the raw HTML file.

  • Every tag, attribute, and piece of text becomes a node.
  • Node relationships: Parent Child Sibling
  • The root of everything is document.
  • Change the DOM and the browser updates the screen. That is why it is called "live".
InteractiveStep 1 / 5
HTML
<html>
  <head><title>Page</title></head>
  <body>
    <h1>Hello</h1>

</html>
JavaScript
// walking the tree from the root
console.log(document.body.parentNode);          // <html>
console.log(document.body.children);            // h1, p
console.log(document.querySelector("h1").nextElementSibling); // <p>
03

Selecting Elements

To change an element you must first get a reference to it. There are five common methods.

MethodReturns
getElementById()Single element
getElementsByClassName()HTMLCollection
getElementsByTagName()HTMLCollection
querySelector()First match
querySelectorAll()NodeList (all matches)
Modern preference

Prefer querySelector and querySelectorAll. They accept any CSS selector (#id, .class, ul > li), so one pair of methods covers everything.

JavaScript
const title = document.getElementById("title");          // one element
const cards = document.getElementsByClassName("card");   // HTMLCollection
const items = document.getElementsByTagName("li");       // HTMLCollection

const first = document.querySelector(".card");           // first match
const all   = document.querySelectorAll("ul > li");      // NodeList

console.log(first.textContent);
Watch out

If nothing matches, getElementById and querySelector return null. Calling a property on null throws a TypeError, so check before you use the result.

04

NodeList vs HTMLCollection

Both look like arrays, but neither is one. They behave differently in two important ways: whether they stay in sync with the page, and what methods they offer.

FeatureNodeListHTMLCollection
Returned byquerySelectorAll()getElementsByClassName(), getElementsByTagName(), .children
Live?Static for querySelectorAll()Live: updates when the DOM changes
forEach()YesNo
Index access [0]YesYes
Can containAny node type (for childNodes)Elements only
JavaScript
const nodeList = document.querySelectorAll(".card");
nodeList.forEach(card => card.classList.add("seen"));   // works

const coll = document.getElementsByClassName("card");
// coll.forEach(...)  -> TypeError: not a function

Array.from(coll).forEach(card => card.classList.add("seen"));
[...coll].map(card => card.id);                          // spread works too
Live collections

If you loop over a live HTMLCollection while adding or removing matching elements, the collection changes under you and the loop can skip items. Convert it with Array.from() first when you plan to modify the DOM inside the loop.

Changing Text
in the DOM

Three properties read and write an element's content. They look similar but behave differently.

PropertyWhat it doesSecurity
innerHTMLReads/writes HTML (understands tags)Risky (XSS)
textContentReads/writes plain text onlySafer
innerTextPlain text, aware of CSS visibilitySafe
BehaviorinnerHTMLtextContentinnerText
Parses HTML tags✓✕✕
Safe for user input✕✓✓
Respects CSS (skips hidden text)✕✕✓
Returns text of hidden elements✓✓✕
Triggers layout (slower)✕✕!
JavaScript
const box = document.querySelector("#box");

box.textContent = "Hello <b>World</b>";   // shows the tags literally
box.innerHTML   = "Hello <b>World</b>";   // World appears bold
box.innerText   = "Hello World";              // plain text, CSS-aware

console.log(box.textContent);   // read text
Try it · same string, three properties

Writing Hello <b>bold</b> <i>italic</i> using: (click a button)
XSS warning

Never put user-supplied text into innerHTML. A string like <img src=x onerror=alert(1)> will run as code. Use textContent unless you really need HTML.

06

Changing Styles
with the DOM

Every element has a style object that maps to its inline style="" attribute.

JavaScript
const el = document.querySelector("h1");

el.style.color = "red";
el.style.backgroundColor = "#C84B1F";   // camelCase, not background-color
el.style.fontSize = "32px";             // values are strings with units

el.style.setProperty("--theme", "tomato");   // CSS variables
el.style.color = "";                         // empty string removes it

console.log(getComputedStyle(el).color);     // final computed value
Try it · element.style
Style me with JavaScript
Remember

CSS properties with a hyphen become camelCase in JavaScript: background-color → backgroundColor. Also, element.style only reads inline styles. To read a value that comes from a stylesheet, use getComputedStyle(element).

Best practice

For more than one or two style changes, toggle a CSS class instead of setting many inline styles. It keeps styling in CSS and is easier to undo.

07

classList

classList is the clean way to work with an element's classes without touching the whole className string.

MethodWhat it does
classList.add()Adds one or more classes
classList.remove()Removes a class
classList.toggle()Adds if missing, removes if present. Great for dark mode, menus, modals
classList.contains()Returns true or false: does the class exist?
classList.replace()Swaps an old class for a new one
JavaScript
const menu = document.querySelector(".menu");

menu.classList.add("open");               // add
menu.classList.add("big", "rounded");     // add several
menu.classList.remove("open");            // remove
menu.classList.toggle("dark");            // on, then off, then on...
menu.classList.toggle("dark", true);      // force: only ever adds

if (menu.classList.contains("dark")) {
  console.log("dark mode is on");
}

menu.classList.replace("big", "small");   // returns true if it replaced
Try it · live classList

Spelling

The method is contains() with an s, not contain(). Writing classList.contain() throws a TypeError.

08

Check yourself

Question 1Which element does the render tree leave out?

Correct. display: none removes the element from the render tree. Hidden and transparent elements still take up space.

Question 2What does querySelectorAll() return?

Correct. It returns a NodeList of all matches. It does not update when the DOM changes later, and it supports forEach().

Question 3Which property is safest for showing text typed by a user?

Correct. textContent treats everything as plain text, so injected tags are shown, not executed.

Question 4What does classList.toggle("open") do when "open" is already present?

Correct. toggle adds the class if it is missing and removes it if it is present.
