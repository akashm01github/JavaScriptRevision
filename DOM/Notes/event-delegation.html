01 / 09

The core idea

Instead of wiring a click listener to every child, listen once on their common parent. When an event arrives, inspect event.target to work out which child started it.

✳ In one sentence

Event delegation uses one parent event listener to handle events from multiple child elements.

one listener · JavaScript
parent.addEventListener("click", (event) => {
  console.log(event.target); // Which child began the click?
});
small-list example · HTML + JavaScript
<ul id="users">
  <li>Akash</li>
  <li>Rahul</li>
  <li>Priya</li>
</ul>

const users = document.querySelector("#users");
users.addEventListener("click", (event) => {
  if (event.target.tagName === "LI") {
    console.log(event.target.textContent);
  }
});
02 / 09

Why it works: bubbling

Most browser events travel up through the DOM after they happen. A click that starts on an <li> passes through its ancestors—so the parent can hear it.

↗ Event propagation

A click is dispatched at its origin, then normally bubbles upward through ancestors. Delegation listens during this bubbling phase.

! Not every event bubbles

Some events (such as focus and mouseenter) do not bubble. Use bubbling alternatives like focusin or mouseover when appropriate.

bubbling path · DOM
// Click on <li> → parent <ul> → <body> → document
users.addEventListener("click", handleUserClick);
03 / 09

Target vs. current target

These two properties answer different questions. Keep them straight and delegated handlers become much easier to reason about.

PropertyPoints toIn a delegated clickStays the same?
event.targetThe deepest element where the event originatedThe clicked child (or a nested element inside it)Can vary
event.currentTargetThe element with the listener currently runningThe parent, e.g. the <ul>Listener's element
inspect both · JavaScript
users.addEventListener("click", (event) => {
  console.log(event.target);        // actual clicked element
  console.log(event.currentTarget); // the <ul> listener
});
04 / 09

One listener, not a crowd

For a short, fixed list, either approach can work. With many children—or children that change—delegation keeps the event wiring in one place.

ApproachListenersWhen children are addedBest fit
Listener on every childN listeners for N childrenAttach another listener to each new childSmall, fixed set
Event delegationOne on the parentNew children work automaticallyLists & changing UIs
the two wiring patterns · JavaScript
// Without delegation: wire each child separately.
item1.addEventListener("click", handleItem);
item2.addEventListener("click", handleItem);
item3.addEventListener("click", handleItem);

// With delegation: one shared parent listener.
parent.addEventListener("click", (event) => {
  const item = event.target.closest("li");
  if (item && parent.contains(item)) handleItem(item);
});

✳ Keep perspective

Delegation is a useful pattern, not a rule that every listener must be delegated. Choose the simplest approach for the behavior and elements you have.

05 / 09

New elements, no rewiring

Because the listener lives on the lasting parent, it can handle matching children added later. The new item bubbles to that same parent when clicked.

add after listening · JavaScript
const users = document.querySelector("#users");

users.addEventListener("click", (event) => {
  const item = event.target.closest("li");
  if (item && users.contains(item)) {
    console.log(item.textContent);
  }
});

// Add later: the same parent listener handles this item.
users.insertAdjacentHTML("beforeend", "<li>New User</li>");
// This also works (the <ul> stays put; its children are replaced):
users.innerHTML += "<li>Another User</li>";

↗ The key detail

Attach the listener to a parent that remains in the DOM. If you replace that parent itself, the replacement does not inherit its old listener.

Waiting for a click…

Listener on ul#users · nested button click → event.target is the exact clicked node · event.currentTarget is the list.

robust delegation · JavaScript
users.addEventListener("click", (event) => {
  const item = event.target.closest("li");
  if (!item || !users.contains(item)) return;

  console.log(item.textContent.trim());
  console.log(event.target);        // exact click target
  console.log(event.currentTarget); // the <ul>
});
07 / 09

Patterns & flags

The idea is simple; a couple of small checks make real-world delegated handlers reliable and safe.

match, scope, handle · JavaScript
users.addEventListener("click", (event) => {
  if (!(event.target instanceof Element)) return;
  const item = event.target.closest("li[data-user]");
  if (!item || !users.contains(item)) return;
  handleUser(item);
});
Watch forWhy it mattersPractical response
Nested elementstarget may be a span or icon inside the row, not the row itself.Use closest() to find the intended matching ancestor.
Unrelated descendantsA broad selector can accidentally handle a nested or unrelated match.Scope with a specific selector; confirm the match belongs to the parent.
Non-bubbling eventsSome events do not travel up to the delegated listener.Use a bubbling counterpart (for example, focusin), or attach directly / use capture when suitable.
Propagation stoppedAnother handler may call stopPropagation() before the event reaches your parent.Check the other handler; keep event flow intentional.
Clickable semanticsA click-only custom element may not behave like a native keyboard control.Prefer real <button> or link elements for interactive actions.

! A common trap

A bare event.target.tagName === "LI" check fails when the user clicks a nested element inside the list item. Match the intended ancestor instead; also note closest() returns the element itself when it matches.

Take it with you

One parent listener can serve many children—including children that arrive later—because their events bubble up to it.
